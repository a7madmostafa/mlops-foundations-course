Self-paced course

From ML to MLOps

A hands-on course that takes a single US Flight Delays project from a fragile notebook to an engineered, tested, packaged, served, monitored, and automated ML system. You already know how to train a model — this course teaches what it takes to operate one.

by Ahmad Mostafa

Who this is for

  • ML practitioners who train models in notebooks
  • Data scientists going from experiments to production
  • Python-savvy people new to software engineering
  • Learners who want the "engineering" half of MLOps

Assume ML + pandas + scikit-learn. No DevOps, testing, or web experience required.

What you'll be able to do

  • Turn a notebook into an installable, maintainable project
  • Structure code, manage dependencies, and configure per machine
  • Test, log, and debug ML pipelines with confidence
  • Track experiments, version data, and orchestrate training
  • Serve the model behind an API, then containerize it
  • Monitor drift, automate CI/CD, and ship like a team

Problem → Concept → Tool → Apply to the Flight Delays project → Practice — the rhythm of every lesson.

Before you start

Start at Module 01 and work forward — every lesson leaves the flight-delay project visibly better and still runnable. Each lesson ships a reading page, the project's CODE/ after the change, and notebook exports you can read in any browser.

  • One project, eight modules. You predict US Flight Delays (arrival ≥ 15 min late) from real BTS on-time-performance data.
  • Each lesson has a verifiable milestone. "What changed?" is answered with a diff against the previous lesson's CODE/ and a command that proves it.
  • No build tooling needed. Open any reading page directly in a browser. The repo clones-and-runs: data and example config are shipped.
  • Documentation and tools are taught as they're needed — nothing appears before the problem it solves.

The project

US Flight Delays, all the way through

One binary-classification project — will this flight arrive 15+ minutes late? — is taken through the whole engineering journey. Real BTS on-time-performance data for January 2024 ships with every lesson, so you can reproduce every step from a clean clone.

  • Lesson 1.1 starts you in a deliberately fragile notebook and lets you name its problems.
  • Every later milestone refactors, packages, tests, serves, containerizes, monitors, or automates the same project.
  • Verify every step by diffing one lesson's CODE/ with the previous one and running the lesson's verify command.
